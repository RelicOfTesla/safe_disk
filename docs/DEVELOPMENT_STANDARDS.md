# Safe Disk 开发规范

本规范适用于产品代码、测试、设计文档和提交。它定义最低工程门槛，不替代模块设计文档或平台验收。

## 1. 范围与简化

- 先实现需求的安全主路径和可验证边界；没有明确价值的状态、开关、兼容层或视觉细节不得扩张为新功能。
- 同一问题反复依赖 UI 微调、计时或复杂状态机才能成立时，先回到需求文档，收窄验收条件或删除非必要能力；不得用更多代码掩盖不清晰的需求。
- 新功能或缺陷修复先登记 [TODO.md](TODO.md)，写清验收条件、未覆盖边界和初始进度；已有任务可直接在该任务下实施。
- 只有自动化实际功能证据和约定的平台验收都满足时，才能宣称完成或提升到 100%。

## 2. 用户文案与多语言

- 所有产品可见文本，包括 `Text`、`Tooltip`、`Semantics`、按钮、菜单、对话框、SnackBar、空态和错误建议，必须通过 `AppLocalizations` / ARB 提供；不得在生产 widget 中新增中文或英文 fallback。
- 服务、controller、FFI 和 domain model 只返回稳定错误类型、状态枚举或结构化参数，不返回已翻译文本。UI 层持有 `BuildContext` 后再映射 ARB。
- 协议字段、错误码、日志、断言、测试夹具和用户不可见诊断不得翻译；它们必须使用稳定、可检索且不含敏感信息的标识。
- 新增或修改可见文案时，同时更新 `app_zh.arb` 与 `app_en.arb`，保持键和占位符一致；关键用户流程必须有中文和英文 widget/Semantics 覆盖。
- 每个本地化批次运行 `dart run tool/audit_i18n_strings.dart`。审计为零只证明源级迁移，不能代替桌面字号、截断、键盘和读屏验收。详细规则见 [I18N_DESIGN.md](design/I18N_DESIGN.md)。

## 3. 安全与错误边界

- 不向子窗口、日志、可见错误或翻译占位符传递密码、密钥、明文内容、完整加密路径或 root session ID；子窗口只接收最小 capability token。
- 失败默认关闭：格式、权限、会话、并发或原子提交无法确认时，不假设成功，不删除恢复证据，也不把未验证状态标记为已完成。
- 跨层错误使用稳定标识和结构化参数；用户详细错误仅在设置允许后显示，并先经过脱敏。
- 加密数据、名称和配置的变更必须保留旧格式、故障注入、错误密码和跨层互通测试；不能仅以 UI 或 mock 测试代替 sec/FFI 验证。

## 4. 异步与资源所有权

- 每个异步操作都必须定义唯一所有者、取消/超时语义、完成后的资源释放，以及失败后的可恢复状态。
- 对 root、文件、窗口、保存队列等共享资源，先确定串行化边界和快照校验点；不能仅依赖 UI 禁用按钮防止竞态。
- 不可逆操作放在所有必要确认和持久化之后。若底层关闭不是原子的，文档和错误处理必须明确部分成功的后果，不能承诺不存在的回滚。
- `dispose`、窗口关闭和会话结束路径必须可重复调用且不访问已释放的 channel/engine；新增生命周期逻辑需要覆盖成功、失败、超时和对象消失。

## 5. 测试与验收

- 缺陷测试优先复现用户报告的最短路径，再验证修复后的不变量；不得只用与真实问题无关的断言制造“覆盖”。
- 测试断言应验证行为、状态、调用边界和安全不变量，避免依赖无关的特定语言文案、时间片或内部实现顺序。需要验证文案时，明确注入 locale 并把文案本身作为需求断言。
- 纯 Dart/Go 单元测试不能替代 UI、FFI 或真实文件系统边界测试。新增跨层功能至少覆盖相应的 sec、FFI、Dart 与公开 UI/CLI 路径，按模块设计补真实平台验收。
- 先运行最小定向测试定位问题；变更完成后运行格式化、静态分析和受影响范围回归。涉及 FFI、安全格式或共享入口时，提交前运行真实 FFI 的完整 Flutter 回归。

## 6. 代码与提交检查表

提交前逐项确认：

1. 使用 `dart format`、`gofmt` 或对应格式化工具，且静态分析无新增问题。
2. 新增 UI 文案已进入 ARB；服务层没有新增翻译文本或未经脱敏的异常回显。
3. 异步失败、取消、重复调用和资源释放路径已审查；没有把 mock 成功当作原子性或平台保证。
4. 已运行定向测试；需要时已运行 `flutter analyze --no-pub`、真实 FFI 完整 Flutter 回归、`go test`/`go vet`。
5. `git diff --check` 通过；只暂存本轮文件，不提交用户未跟踪或无关改动。
6. [TODO.md](TODO.md) 与相关设计文档如实记录已验证证据和剩余缺口，不以“设计完成”替代实现完成。

本规范的修改必须使用中文，并同时评估对 [I18N_DESIGN.md](design/I18N_DESIGN.md)、[TODO.md](TODO.md) 和测试门槛的影响。
