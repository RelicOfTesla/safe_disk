# 系统文件剪贴板范围设计

## 状态

当前版本明确不把加密 root 中的文件或目录注册到操作系统的文件剪贴板。

应用内的 `SecureClipboardService` 是当前文件复制、剪切和粘贴的正式实现。它只保存 root session、逻辑路径和操作类型，不把明文文件内容或临时明文路径写入系统剪贴板。

## 不直接接入的原因

操作系统文件剪贴板通常要求提供可被其他进程读取的文件 URI 或本地路径。加密 root 的 backing path 不是用户可用的明文文件；若要支持外部文件管理器粘贴，至少需要：

1. 在 root 外创建明文 staging 文件。
2. 在外部进程读取期间保持 staging 文件可用。
3. 监听取消、超时、进程退出和外部读取完成事件。
4. 在 Windows、macOS、Linux 上分别处理剪贴板格式、文件锁和删除失败。

任何一个生命周期遗漏都可能把明文文件留在磁盘，或让系统剪贴板长期持有失效/泄露的路径。因此不能用 `Clipboard.setData` 写入逻辑路径，也不能把临时导出目录伪装成系统文件剪贴板互通。

## 当前可用能力

- 应用内文件剪贴板支持复制、剪切、批量条目、跨 root 复制、同 root 移动和冲突处理。
- 粘贴状态只显示在 Safe Disk 界面内，结束会话或自动锁定时按 root session 清理。
- “复制名称”和“复制逻辑路径”是用户主动触发的明文文本操作，不等同于系统文件剪贴板；这两项会明确提示内容已进入系统剪贴板。

## 后续若重新立项的前置条件

只有同时定义以下内容后，才允许实现系统文件剪贴板：

- 明文 staging 的目录、权限、命名和磁盘空间上限。
- 最长存活时间、外部读取确认、取消和进程异常清理。
- 加密 staging 或受控 broker 是否可被目标文件管理器识别。
- 三个平台的 URI/文件列表格式、锁语义和删除失败恢复。
- 退出、自动锁定、结束会话和系统剪贴板继续持有 URI 时的安全策略。
- 能证明明文不会残留的跨层集成测试和桌面实测。

在这些条件未满足前，继续使用应用内安全文件剪贴板是有意的产品边界，不把“系统文件剪贴板互通”作为当前版本的未完成实现偷偷补上。
