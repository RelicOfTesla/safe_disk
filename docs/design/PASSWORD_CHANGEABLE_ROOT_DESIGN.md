# 可改密码加密目录设计

## 状态

核心实现已完成并有 sec、Go FFI、Dart FFI 与 widget 回归；sec 已覆盖损坏 envelope 失败关闭、临时配置无法创建时旧密码保持可用、替换失败时正式配置字节不变，以及跨进程锁的等待和释放。锁文件位于用户缓存，使用 canonical root path 的摘要命名，不污染用户目录。适用范围是新建 root；已有“密码直接派生内容密钥”的目录保持只读兼容，不能伪装为可改密码。进程在 replace 前后被强制中断和三平台配置替换/锁仍待验收。

## 目标与边界

- 创建时可明确选择“允许以后修改密码”，默认启用。
- 改密后，新的密码可以打开原有文件和加密名称；旧密码必须失败。
- 改密不重加密文件、不移动目录、不写入明文临时文件。
- 密码输入、派生密钥、内容密钥和包装密钥只在 native 层短暂存在，并在可控对象结束时清零。
- 旧格式、损坏的包装记录、未支持的版本均失败关闭；不会回退为“尝试使用密码直接打开”。

不包含多密码槽、恢复密钥、密钥托管、跨目录共享密钥或旧目录原地升级。这些能力需要独立的威胁模型与格式版本。

## 格式

新格式在 `_cryption.json` 中写入：

| 字段 | 含义 |
|---|---|
| `sec_key_envelope_version` | 内容密钥包装格式版本，首版为 `1` |
| `sec_key_envelope_nonce` | AES-256-GCM 随机 nonce，Base64 |
| `sec_key_envelope_ciphertext` | 经过认证加密的随机内容密钥，Base64 |

创建时按所选数据/名称算法所需的长度生成随机内容密钥。现有 KDF 仍保存其 salt 和参数，但其输出固定为 32 字节的包装密钥；该包装密钥用于：

1. 认证用户密码。
2. 以 AES-256-GCM 加密内容密钥，关联数据固定为格式域 `safe-disk/root-key-envelope/v1`。

打开时先从密码派生包装密钥，校验密码认证记录，再解开并认证内容密钥。文件和名称加密上下文只接收内容密钥，因此改密不会改变任何已有密文。

## 改密事务

1. 从原配置派生旧包装密钥，认证并解封内容密钥。
2. 以 canonical root path 摘要获取用户缓存中的跨进程排他锁；等待时可由调用方 context 取消。
3. 将原配置复制到同目录、同权限域的临时文件。
4. 仅在临时配置中为新密码生成新的 KDF 参数、密码认证记录和内容密钥包装记录。
5. 同步临时文件，然后原子替换正式配置并同步父目录（平台支持时）。
6. 任一步失败时删除临时文件；正式配置和旧密码保持可用。

UI 收集密码后会先关闭可安全关闭的当前 root 会话，再调用 native 改密并保留侧边栏历史；无论改密成功或失败，用户都需要重新解锁。成功时必须使用新密码，失败时旧密码仍应可用。这样不会让旧密码建立的会话继续以“已改密”状态运行。

## 兼容与错误

- 不含 `sec_key_envelope_version` 的配置是旧格式：可以打开，改密 API 返回明确的“不支持”。
- 版本未知、nonce/ciphertext 缺失或格式错误、认证失败：打开失败，不尝试旧格式回退。
- UI 属性仅显示“支持”或“不支持”，不显示 nonce、密文、salt、验证标签或密钥材料。

## 验收

- sec：创建可改密码 root、写文件和目录、改密、旧密码拒绝、新密码重开后内容/名称完整。
- sec：错误旧密码、损坏包装记录、旧格式改密拒绝、临时写入失败时旧密码仍可打开。
- FFI/Dart：创建选项与改密接口跨层传递，错误可分类。
- UI：创建选项默认启用，属性状态准确，改密确认和校验完整，成功后锁定会话。
- 平台：Linux/Windows/macOS 的配置替换、句柄占用和进程中断实测；未完成前不能标记为跨平台完成。
