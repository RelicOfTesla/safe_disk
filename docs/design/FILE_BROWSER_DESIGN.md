# 文件浏览器视图与筛选设计

> 状态：2026-07-14 已实现 list/grid/tree 职责拆分、当前目录筛选、共用排序、批量文件导出和批量删除基础；大目录分页与全 root 搜索仍未实现。

## 1. 核心决策

- `list` 与 `grid` 是同一“当前目录内容区”的两种表现方式，二者共享路径、筛选、右键选择和批量选择状态。
- `tree` 是目录导航器，不是第三种内容表现方式。打开 tree 后仍保留 list/grid 内容区。
- 当前已有的名称匹配只作用于已加载的当前目录，应明确称为“筛选当前目录”，不能称为全 root 搜索。
- 真正的全 root 搜索需要 walker/分页、取消、错误传播和结果路径展示，在这些能力完成前不复用当前筛选入口。

## 2. 响应式布局

### 宽屏

- 左侧 root 历史栏由主界面负责。
- 文件浏览器内部可展开一个约 240 像素的目录树导航面板。
- 右侧内容区继续显示 list 或 grid。
- tree 开关与 list/grid 切换分开，避免一个按钮承担两种维度。

### 窄屏

- tree 不常驻挤压内容区。
- 点击“目录导航”后使用临时面板展示，选择目录后关闭面板并导航。
- list/grid 切换仍留在工具栏。

## 3. 导航与筛选状态

- breadcrumb、Go up、tree 选择和打开子目录都属于路径导航。
- 任一路径导航发生时自动清空当前目录筛选，禁止把上一个目录的结果带入新目录。
- 筛选输入框不替换 breadcrumb，用户始终能看见当前作用域。
- 回车只重新应用筛选并保持输入焦点，不触发路径导航。
- 清空筛选后立即恢复当前目录完整列表。

## 4. 选择与右键

- 右键按下立即设置 `contextSelectedPath`，list/grid 使用相同语义。
- 高亮必须同时具有高对比背景和明确边框/指示条，不能只用低透明度颜色。
- 点击内容空白区清除右键选择；路径导航也清除右键选择。
- tree 的当前路径高亮独立于文件条目右键选择。
- 属性面板只消费 walker 已返回的 entry 元数据，不在首击路径执行 FFI 或磁盘读取；右键菜单和属性面板不使用过渡动画，普通属性值不初始化文本选择管线，复制名称/路径由独立菜单动作承担。

## 5. Root 历史与会话操作

侧边栏关闭按钮是 root 操作入口，而不是单义的“移除”按钮。必须提供三个互斥动作：仅结束解锁会话并保留历史；结束会话并移除历史但保留磁盘；结束会话、移除历史并递归删除所选实体目录。第三项必须显示完整路径并要求输入目录名二次确认，不能复用普通确认框。三项都必须先处理活动写入和内容窗口阻断，再释放 root session 和对应应用内剪贴板引用。

## 6. tree 数据边界

- tree 只显示目录，不显示文件，避免点击文件却按目录导航。
- 子目录按需加载；加载错误必须可见，不能静默显示为空。
- 当前 `FileService.listCurrentDirectory(offset/limit)` 会先读取完整 FFI 列表再本地 `skip/take`，不是分页；真实目录 cursor 方案见 [DIRECTORY_PAGINATION_DESIGN.md](DIRECTORY_PAGINATION_DESIGN.md)。

## 7. 文件剪贴板状态

- 应用内文件剪贴板是主内容区状态，不是系统文本剪贴板。
- 有内容时显示紧凑状态条：来源条目、当前粘贴目标、粘贴和清除。
- 顶部 AppBar 不再保留重复粘贴按钮。
- 窄屏使用图标操作和截断文本；宽屏可显示完整动作标签。

## 8. 后续全 root 搜索

如实现真正搜索，应新增独立入口和结果页面，至少包含：

- 递归 walker 或分页搜索 API；
- 取消与资源上限；
- 每个结果的完整逻辑路径；
- 名称解密/损坏错误传播；
- 从结果进入所在目录时清理搜索状态；
- 10 万条目性能基线。

在此之前，UI 文案统一使用“筛选当前目录”。

## 9. 排序与批量选择

- list/grid 使用同一排序状态，当前支持名称升降序、修改时间新旧和大小升降序。
- 目录始终排在文件前；未知时间/大小固定排在已知值之后，避免降序时未知值出现在顶部。
- 排序只作用于当前已加载目录，不宣称对未加载分页或全 root 生效。
- 文件右键可进入选择模式；当前支持全选文件、批量导出和批量删除，目录不进入该批量模型。
- 单文件与批量文件导出默认拒绝覆盖；目标存在时必须选择取消、保留两者或替换，只有明确替换才允许覆盖。
- 批量删除明确为逐项执行而非原子事务；成功项移出选择，失败与未处理项保持选择，便于重试。
- 应用内剪贴板区分复制和剪切：同 root 且不替换时移动使用 rename；跨 root 文件移动严格按 copy 成功后再 delete 源文件执行，删除失败时保留两份并报告部分失败。
- 多选文件按当前目录显示顺序写入一次性应用内队列；逐项粘贴并逐项解决名称冲突，成功项立即移出，失败、取消及未处理项保留重试。同批次成功生成的名称必须加入目标名称集合，禁止后续条目在批次内部静默覆盖。
- 窄窗口下固定侧栏偏好临时降级为抽屉，选择历史 root 后自动关闭抽屉；窗口恢复到 720px 以上后继续使用原固定偏好，不改写持久化设置。
- 跨 root 目录移动已使用目标 root `copyBySession` 成功后删除源目录的语义；删除失败固定报告部分完成并保留源、目标和剪贴板项，不能将仅复制后保留源目录报告为移动成功。详见 [CROSS_ROOT_DIRECTORY_MOVE_DESIGN.md](CROSS_ROOT_DIRECTORY_MOVE_DESIGN.md)。
- 批量复制和移动已提供“全部保留两者/全部替换”、显式取消与结构化结果面板；结果区分成功、跳过、失败、未处理及剪贴板剩余项，并展示截断后的失败原因。

### 批量冲突策略

批量粘贴的冲突策略属于单次执行上下文，不写入设置，也不修改后续粘贴默认行为。第一次冲突可选择：取消剩余操作、仅此项保留两者、仅此项替换、本次后续冲突全部保留两者、本次后续冲突全部替换。选择“全部”后，后续同类名称冲突不得再次弹窗；若某项执行失败，继续处理仍安全的后续项，但失败项保留在应用内剪贴板。

取消是显式的批次终止：当前冲突项和所有未处理项保持队列，之前成功项已移除，不能把取消显示为失败或完成。结果摘要至少包含成功、失败、取消/未处理和剩余队列数量；失败详情可以截断展示，但不得只报告成功数。

“全部替换”不是绕过安全判断的全局覆盖开关。它只自动应用于源与目标类型一致且不是同一条目的后续冲突；遇到同一条目或类型不兼容时必须重新询问。批次策略对象只在一次粘贴调用内创建，完成、取消或异常退出后立即失效。

## 导航模型与预览范围

当前版本采用“目录浏览器 + 显式打开 + 可选新窗口”的导航模型，不实现标签页和隐式文件预览。

- list/grid/tree 只负责目录导航、选择和操作。
- 单击或双击打开由设置决定，打开文件进入主窗口路由。
- “在新窗口中编辑/查看”显式申请内容窗口 lease，由 broker 管理读写、草稿、关闭和自动锁定。
- 快捷键属于文件浏览器或内容窗口自身，不建立另一个隐藏的导航状态。

## 暂不实现标签页

标签页会引入一套额外的文档状态容器：每个标签需要持有 root session、目录路径、文件 lease、脏状态、草稿恢复和关闭确认。若同时保留现有子窗口协议，主窗口标签与子窗口还会产生同一文件的并发编辑冲突。

在没有统一导航状态和关闭协议前，继续使用 Flutter 路由与显式原生窗口更容易证明以下不变量：

- 关闭文件窗口只关闭自己的 lease，不影响其它 root 或文件窗口。
- 结束 root session 前可以枚举并处理所有内容窗口。
- 自动锁定可以等待草稿保存，再撤销窗口能力。
- 同一文件的并发保存仍由 broker 的 revision 检查拒绝过期写入。

## 暂不实现悬停/单击预览

预览并不是只渲染一个缩略图。它必须在用户移动鼠标或切换焦点时解密内容，并定义预览 lease 的超时、取消、内存上限、错误展示和读写隔离。对文本和图片还要分别处理大文件、动画、系统 codec 和草稿冲突。

当前单击/双击模式已经有清晰语义：单击可选择或聚焦，打开动作由设置决定；用户需要查看内容时显式打开。这样不会因悬停误解密，也不会把预览内容误当作已经打开的文档。

## 未来重新立项的前置条件

只有明确以下内容后，才重新实现标签页或预览：

- 标签/预览与 root session、document lease、草稿和自动锁定的生命周期协议。
- 文本和图片各自的解密、内存、取消、错误和只读策略。
- 同一文件多标签/多窗口的冲突展示与保存决策。
- 导航快捷键、焦点、读屏语义和三平台原生窗口行为。
- 能证明预览关闭后不会残留密钥、明文缓冲区或未关闭 lease 的跨层测试。

在这些前置条件未完成前，显式打开不是“缺少预览”的临时实现，而是当前版本的安全产品边界。
