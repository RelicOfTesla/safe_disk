# 错误报告与安全诊断设计

## 1. 目标

默认提示应面向普通用户，只显示失败动作、原因类别和可执行建议。用户在“设置 → 报告详细错误信息”显式开启后，错误提示额外显示错误类型、操作阶段和底层错误，便于定位 FFI、文件系统与平台打包问题。

首版不写磁盘日志。加密文件管理器若默认把路径、异常对象和操作上下文写入明文日志，会形成新的持久泄漏面；当前采用进程内、按次展示和用户主动复制的方式。后续若增加日志，必须独立设计加密存储、容量上限、清理周期和用户导出确认。

## 2. 信息分层

- 友好层：错误标题、描述和建议，详细开关关闭时始终可用。
- 诊断层：稳定的 `ErrorType`、操作阶段和底层异常，仅在开关开启且调用方提供原始错误时显示。
- 原生层：Dart FFI 使用 `NativeOperationException` 保留 C ABI 操作名和 Go 返回消息，不再只抛无阶段的通用 `Exception`。

创建 root 将阶段拆为 `validate-create-root-path`、`create-root-config`、`open-created-root` 和 `load-created-root-config`。因此“创建失败”可以区分目录状态、DLL/FFI、root 打开和配置解析，而不是统一建议检查权限。

## 3. 脱敏边界

集中脱敏器在展示和复制前处理原始错误：

- 隐藏 `password`、`passphrase`、`secret`、`token`、派生 key 及密码环境变量的值；
- 隐藏命令行 `--password` 系列参数值；
- 用户主目录替换为 `~`，但保留其余路径和操作系统错误码，因为路径与错误码是诊断权限、盘符和 bundle 问题的必要证据；
- 单次详情限制为 4096 个字符，超出后明确标记截断；
- 不记录密码、派生密钥、文件正文，不自动落盘。

脱敏是最后防线，不代表上游可以把敏感值拼入异常。新接口仍应优先返回结构化错误码和安全上下文。

## 4. Windows 创建 root 诊断

Windows 原生库的规范文件名是 `ffi_sec_fs.dll`。此前构建脚本生成 `libffi_sec_fs.dll`，而 Dart 固定加载 `ffi_sec_fs.dll`，可能导致找不到库或从 `PATH` 误加载旧版本。当前约束为：

1. `scripts/build.go` 在 Windows 只生成并复制 `ffi_sec_fs.dll`；
2. Windows CMake 必须把该 DLL 安装到 `safe_disk.exe` 同目录，缺失时构建直接失败；
3. Dart 只按可执行文件目录的绝对路径加载，不回退到 `PATH`；
4. 创建流程允许选择不存在的目录，但已存在目录必须为空；非空目录在进入密码和 FFI 前明确拒绝且不修改原内容。

## 5. 验证状态

- 详细开关默认关闭、持久化、设置保存事务和应用启动加载已有测试；
- 开关关闭不显示底层错误，开启后显示操作阶段与脱敏详情已有 widget 测试；
- 密码、环境密码脱敏及路径保留已有单元测试；
- Windows DLL 名称有 Go 单元测试，构建脚本和 sec_fs 均已通过 Windows amd64 交叉编译；
- Flutter 真实 FFI 全量回归 114 项通过。

仍需 Win10 实机复验：bundle 中 DLL 名称与加载路径、创建不存在/空目录、权限拒绝错误内容，以及 100%/125%/150% 缩放比下的字体清晰度。
