# 安全图片查看器设计

> 状态：2026-07-14 资源边界与真实格式验收进入实现阶段。本文描述当前目标，不把仅按扩展名识别视为格式支持。

## 1. 安全边界

图片明文只允许存在于进程内存，不写入临时文件。查看器采用两级资源限制：

- 编码明文最大 64 MiB。目录列表已有可信大小时，在调用解密接口前拒绝；大小未知时，解密返回后立即复核并清零超限缓冲区。
- 解码尺寸最大 100 MP。编码数据通过 Flutter 引擎 codec 读取宽高后计算像素数，超过上限不得交给 `Image.memory` 解码渲染。
- 原生图片子窗口不能绕过限制。主 engine 的 document broker 在创建图片 lease 时记录相同编码字节上限，后续每次 `document.read` 均再次检查；图片 lease 为只读能力，`save`、草稿和脏状态写入口必须拒绝。子 engine 再执行元数据和像素检查。

64 MiB 与 100 MP 是首版稳定性边界，不代表加密格式上限。未来若实现分块解码，应新增独立接口和内存预算，不能直接提高常量掩盖峰值内存问题。

## 2. 格式真实性

浏览器入口可按扩展名提供候选操作，但“支持”必须由真实内容验证。JPEG、PNG、GIF、BMP 和 WebP 均交给当前 Flutter engine 的 codec 探测；扩展名正确但内容损坏、格式不受当前平台 codec 支持或尺寸非法时，显示可重试的明确错误。

测试必须使用每种格式的有效字节并实际完成 codec 探测和 widget 渲染，不能只断言扩展名集合。

## 3. GIF 动画语义

GIF 不做首帧静态化：在资源上限内沿用 Flutter `Image.memory` 的帧调度自动播放。元数据层扫描 GIF 图像描述块以区分静态和多帧内容，界面显示“动画”提示。首版不提供暂停、逐帧或循环次数覆盖；这些属于后续播放器控制，不影响本轮格式真实性。

## 4. 生命周期与竞态

每次打开、切图和重试生成新的加载代次。旧代次即使晚返回，也必须清零自己的明文字节且不得覆盖当前图片状态。成功切图前清零上一张缓冲区；加载失败、超过资源边界和页面销毁时同样清零。

查看器显式持有 `MemoryImage` provider。切图和销毁时先从 Flutter image cache（包括 live image）逐出 provider，再清零其字节；broker 在替换快照或关闭 lease 时清零自身持有的 `baseContent`。Dart/engine 内部复制仍受运行时生命周期约束，因此文档不宣称进程内所有副本可被绝对擦除。

目录导航继续只读取当前目录图片候选，不宣称跨目录搜索。键盘左右键、按钮和手势共用同一导航状态，加载期间不得并发提交多个相邻切换导致索引与内容错位。

## 5. 错误与可验证性

错误至少区分：内容为空、编码字节超限、解码像素超限、损坏或 codec 不支持、解密失败。错误信息不得暴露 root key、token 或底层明文内容。

自动化证据包括：五类真实格式、静态/动画 GIF、已知大小解密前拒绝、未知大小解密后拒绝、像素上限、损坏内容、异步旧结果丢弃、切图和关闭清零、主/子窗口一致边界，以及现有缩放旋转导航回归。
